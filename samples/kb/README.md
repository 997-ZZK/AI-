# 测试语料（samples/kb）

8 篇合成文档，用来验证「真实 embedding + 阈值」这条链路。刻意做出了四种真实情况：

| 文档 | 覆盖的情况 |
| --- | --- |
| 01 员工手册 | 短文档（432 字、5 个小节）合成一个切片 —— 单主题提问的余弦会被稀释，是阈值误拒的高发区 |
| 02 报销制度（2026 版）+ 03（2024 版，已废止） | 新旧版本措辞几乎一致、数字不同：检索会把废止版排在前面，考验模型会不会照抄旧数字 |
| 04 产品手册 / 05 API 指南 / 06 运维手册 | 长文被切成 2 片；06 与 05 都提到 503，考验排序与引用定位 |
| 07 FAQ（txt）/ 08 配置项（json） | 覆盖 TEXT / JSON 两种 sourceType（JSON 会被拍平成「路径: 值」行） |

## 灌库

```powershell
$kb = 'handbook'
Get-ChildItem samples\kb -File | Where-Object Name -ne 'README.md' | ForEach-Object {
  Invoke-RestMethod -Uri "http://localhost:8080/api/v1/kbs/$kb/documents/upload" -Method Post -Form @{ file = $_ }
}
```

重复上传同一份内容是安全的：入库前会做 contentHash 重复检测。8 篇文档共切出 11 个切片，真实 bge-m3 入库耗时 24.2 秒。

复现单条：

```powershell
$body = @{ query = '忘记打卡怎么办？'; topK = 5; includeContext = $false } | ConvertTo-Json
Invoke-RestMethod -Uri 'http://localhost:8080/api/v1/kbs/handbook/retrieve' -Method Post `
  -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
```

## 已知局限

- 短文档单片多主题时，`sectionPath` 只能定位到片的首节（例：问「打卡与异常」会标成「工作时段」）。
  切片粒度不足时引用标签会粗一档，需要更细的引用要调 `TextChunker` 的 target 而不是调阈值。
- 已废止的 03 分数高于现行的 02（措辞几乎一致，但 03 更短更聚焦）。当前靠正文里的「已废止」标注
  让模型自行避开；要系统性解决，得给文档加状态元数据并在检索侧降权（M4 待办）。
- 问「忘记打卡」时 06 运维手册的「SSE 断流」片会压过正确片：两片都含「重试 / 补 / 失败」这类词面，
  这是纯向量检索的固有噪声，靠 topK 与提示词兜。真正的解法是混合检索（BM25 + 向量），M4 待办。
