# Vision OCR 错误边界

## 目标

`VisionOcrProvider` 通过对话模型完成图片转写。模型供应商返回的错误正文、请求地址、凭证片段和底层异常链属于内部诊断，不能进入 `OcrException`、文档失败原因、HTTP 响应或运行记录。

## 固定契约

- 没有具备 `vision` 能力的档位继续返回固定的「OCR 不可用」提示，保持能力缺失的 503/降级语义。
- 路由调用抛出任意 `RuntimeException` 时统一转换为固定的「OCR 调用失败：视觉识别请求未完成」提示；该文案不触发上传接口原有的「能力不可用」状态码分流。
- 上述转换不设置 cause，也不复制 suppressed 异常；调用方只能按 `OcrException` 和固定文案分流。
- 成功转写、`NO_TEXT`、页数上限和 OCR 开关语义保持不变。
- 本轮只收紧视觉 OCR 适配器及其离线协议桩测试，不改厂商协议、配置、数据库、附件留存或真实模型调用。

## 验证

使用本地 fake `ProviderRouter` 注入带敏感标记的异常正文、cause 和 suppressed 异常，断言异常、文档失败记录和 HTTP 响应均不包含标记；同时回归能力缺失、成功文本和 `NO_TEXT` 路径。真实厂商联调仍后置。
