输入 JSON 版本为 `schemaVersion: 1`，另含 `suiteId`、`goldenVersion`、`cases`。每个 case 使用唯一 `id`、`category`、`scenario`、对象 `input`、对象 `expected`；只用合成事实/记忆/用户话语和固定故障。加载器拒绝空集、重复 id、错误版本、未知字段/类别和缺失预期，测试遇到未知 scenario 必须失败。

报告只含套件/黄金集版本、输入资源 SHA256、case id/类别、固定 PASS/FAIL/NOT_RUN、断言异常类型以及总数/通过率；不保存输入、预期、实际正文、原始异常 message/cause、完整请求或凭证。执行或断言失败时仍写报告；未执行或遗漏场景不能算通过。夹具格式/版本校验失败直接关闭门禁，不产生伪有效评测报告；重复 JSON 字段和首个根对象后的额外 JSON 同样拒绝。

## 场景与门禁

1. **上下文/对话装配**：至少 12 条，覆盖画像→长期记忆→摘要→窗口历史→本轮输入的角色/顺序；窗口字符预算、独立关闭选项；端口读取失败降级；MANUAL 白名单与显式 model/便宜档路由优先级；用户/助手伪装标签不变 system 指令。采集实际 `ChatRequest` 或装配结果，核对独立定义的角色、片段顺序/缺席与调用计数。预览与真实调用继续用存量 API 集成回归核对。
2. **确定性错误/降级**：至少 10 条，覆盖 provider 成功/失败切换/能力缺失、流式已输出后失败不重复输出、软/硬额度、输入/输出安全、节点重试与超时、运行取消和终态收口。复用 `ProviderRouter`、真实节点与 `ExecutionEngine`，通过固定失败/捕获请求/CountDownLatch 注入故障；不靠长 sleep 碰运气。核对状态、事件、可见回复/降级标记、调用/重试次数与 token 计数，不把 mock 回答文本当质量评分。
3. **RAG 引用/拒答/提示边界**：至少 10 条，覆盖无命中/低分拒答、编号与引用元数据、跨 source/doc 隔离、未知顺序、正文分隔符与控制字符、恶意资料只作为数据、保留独立来源映射。走真实后处理/提示词装配，不另造通过器。既有 `RagGoldenSetEvalTest` 的 recall/MRR/拒答门槛和 mock 阈值不变；不改 ANN 查询/索引/性能参数。

RAG 边界修正契约：资料正文和 citation label 的标题/章节均为不可信数据。所有连续 3 个及以上的 `<`/`>` 归为 2 个，避免 4 连字符经单次替换反而留下合法分隔符；标签中的换行/控制符扁平为普通空格，防止在真实正文块外伪造多行规则或边界。清洗只用于提示词显示，输出的引用元数据保持原值以便溯源，不声称这能保证模型抵御所有语义注入。最小修复限定 `ContextPromptAssembler`，黄金集必须包含 4 连/更长、标题和章节攻击样例。

输入安全位于 `SessionMessageService` 的提交入口，工作流纯引擎测试不将输入审核伪装成节点能力。第二层在工作流组另用真实服务入口或已有 API 集成回归验证拒绝输入零 provider 调用，并分别标记其入口。

工作流失败场景同时核对固定错误原因，避免任意异常均能满足 FAILED；部分流失败场景核对完整可见 DELTA 和条数，证明没有重复输出。Recorder 对每个已启动 node run（含独立重试 attempt）核对仅收口一次及其状态；运行取消时也要验证节点失败收口。预览场景仅接受实际调用 provider 的默认继承路径，避免无请求时跳过预览核对。

三组契约各自 **100% 通过**、场景总数至少 32，且各组下限满足；不存在“把失败类别排除后计算通过率”。JUnit 动态用例逐条可见。通用设施另验证坏夹具/未知类别/重复 id/未执行用例不可形成绿色报告。原有 RAG 检索质量指标独立报告，不与契约通过率混为一个分数。

## 实施边界与验收

先完成文档和夹具约定，再新增测试/报告设施；若暴露生产缺陷，先记录可复现场景与契约，再做必要的最小修复。大范围生产重构另出方案，不在黄金集切片顺手做。无新全局/项目依赖，无 API/schema/迁移、`.env`、真实 key、CI/CD 或系统配置改动，不连接真实厂商、不产生付费调用、不删文件或 git 历史、不 push/rebase。

设计可参考聆思本地项目通用的“基线→场景→候选→回归→报告”方法，只读测试/工具结构；不复制私有提示词、业务正文、真实报文或凭证。

验收运行第二层定向测试、相关存量装配/安全/额度/执行/RAG 测试、离线全量测试与打包；生成独立 JAR 和 SHA256、三组脱敏报告及输入/源码哈希快照。若涉及生产记忆/画像装配口径变化，按项目 AGENTS 补真实栈 mock 验证。只新增数据驱动测试且不变装配逻辑时，记录原有集成回归即可。
